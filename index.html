Three ways to read a run.

A prototype for visualizing a VibeSim run — its deployment structure (pools → groups → workers → arch) and its analyzer results (SLO CDFs, throughput, GPU utilization, KV occupancy, kernel time-share). All three share one spine — Run ▸ Pool ▸ Worker ▸ Kernel, where selecting a piece of the machine re-scopes the metrics — and one centerpiece: the cost tree (Sum → · Max ⇉ · Scale ×N · Leaf), flattened so the 94 identical layers collapse into one ×94 container. They differ in how you navigate from the system view into an individual graph. Running on fake data — pick the one that feels right.
