Wiring the agent conversation into viz-ui

The agent already writes a quantitative research log. Every number in it is a real simulation sitting on disk in a layout viz-ui already reads. What's missing is not analysis — it's a way for the argument to point at its own evidence.

So: viz-ui is the host. The orchestrator ↔ implementer card loop moves in, unchanged in substance, re-set in viz-ui's own type and palette. Nothing is re-invented and no third design language is introduced.

The organising metaphor is a printed research paper — the conversation is the article, the analyzer's charts and cost trees are numbered plates, numeric claims are footnote references, and the current selection is a margin annotation. Four directions below, differing only in where the article sits relative to the plates.

orchestrator amber → gold implementer teal → teal answer rose → terra

every direction demonstrates

01
A footnote opens its run. A number inside an implementer note is a citation; one click lands the analyzer on the run that produced it.
02
One round's sweep is one object. Nine runs read as a boundary search with a crossing marker — not nine separate run switches.
03
Select → chip → ask. A worker or cost-tree leaf becomes a composer chip that expands to the literal VizState payload the agent receives.
+
Plus the two states real use is dominated by: a round still working, and a run whose analysis is pending.

what these are

Four standalone HTML files. No build step, no framework, fonts from the Google CDN, a :root block copied from app/src/theme.ts, and a small inline script only for the interactions that must be felt. Every number is invented but internally consistent: Qwen3-32B on one H200, 512 in / 512 out, boundary at 18.6 r/s.

what they are not

Not wiring. No /api/v1/ adapter, no run-catalog generation for workspace runs, no change under app/. The conversation payload is drawn from app/src/store.ts's VizState so the wiring target is unambiguous — but the wiring itself gets designed once a direction is picked.

reference points

Chrome DevTools AI assistance (context pre-selected by where you invoked from, and inspectable), Grafana Assistant (a rail that survives navigation), Hex Notebook Agent (progressive context disclosure), Perfetto (their documented lesson: panes that appear and disappear on selection change confuse people — so no direction mutates its layout when context changes).
